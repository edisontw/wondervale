# Roadmap

## Phase 0 — Foundation

### Product/content foundation
- product vision;
- content strategy;
- character/world bible;
- world continuity rules;
- learning framework;
- parent guidance/experience model;
- accessibility/privacy/safety baseline;
- content versioning/state rules.

### Technical foundation
- content schema direction;
- static-first architecture;
- deployment baseline;
- research/validation plan.

### Exit condition

A writer/designer should be able to outline one real episode without inventing new structural rules, and an engineer should be able to describe how that episode becomes validated runtime content without embedding its story logic in UI code.

## Phase 1 — Content toolchain + application shell

Build the smallest architecture that proves the model:

- web application shell;
- content schemas;
- content compiler/validator;
- dependency/continuity lint;
- story scene runtime;
- activity registry with only the mechanics E01 needs;
- parent cue UI;
- versioned local progress/event ledger;
- derived continuity state;
- accessibility baseline;
- static production build;
- basic automated tests.

Exit condition: a placeholder episode can run end-to-end from structured content and a save can be rebuilt deterministically.

## Phase 2 — Episode 01 vertical slice

Build one real Season 1 Core Episode, not a disposable demo.

Must include:

- recurring characters;
- story hook;
- exploration before explanation;
- at least one substantive interactive activity;
- one meaningful parent-child exchange;
- graduated help;
- recoverable failure;
- visible consequence;
- structured learning evidence;
- structured continuity events;
- narration/read-aloud readiness;
- satisfying ending plus a reason to continue.

Exit condition: real parent-child pairs can complete the episode without developer explanation and the team identifies no foundational format change required before E02.

## Phase 3 — Connected MVP

Expand to 3–4 connected Core Episodes.

Test:

- whether families return;
- whether characters are memorable;
- whether parent cues create conversation;
- whether mechanics already feel repetitive;
- whether world changes are noticed;
- whether previously introduced ideas can be reused naturally;
- whether a returning family can understand a recap after a gap.

Do not add side systems merely to increase feature count.

## Phase 4 — Season 1 alpha

Target roughly 10–12 coherent Core Episodes organized into Story Arcs.

Add as justified:

- callbacks;
- visible location changes;
- character development;
- learning revisit/transfer;
- broader activity mechanics;
- richer accessibility/audio;
- optional Side Stories or Free Explore content.

Run longitudinal content audits for repetition, unresolved promises, and neglected skills.

## Phase 5 — Usage-driven expansion

Only after meaningful usage, evaluate:

- cloud accounts;
- multiple child profiles;
- cross-device sync;
- adaptive challenge;
- authoring CMS;
- multilingual versions;
- dedicated hosting;
- privacy-preserving telemetry;
- additional content types.

Any account, AI, analytics, voice capture, social, payment, or advertising feature requires a fresh privacy/safety review.

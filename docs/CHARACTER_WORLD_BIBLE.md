# Character & World Bible

## Purpose

Recurring characters and a changing town are core learning infrastructure, not decorative IP.

Children should be able to remember:

- who people are;
- what they care about;
- what happened before;
- how a place changed;
- how something learned earlier became useful later.

## Character model

Each recurring character should define:

### Stable core
Traits that should remain recognizable.

- temperament
- interests
- humor style
- communication style
- strengths
- limitations
- fears / dislikes
- values

### Current state
Facts that can change.

- current goals
- knowledge
- relationships
- responsibilities
- ongoing problems
- recent experiences

### Growth arc
A small number of long-term developments.

Examples:

- learns to test ideas before jumping to conclusions;
- becomes more comfortable asking for help;
- learns to listen to another person's perspective;
- becomes more patient when plans fail.

Growth should emerge through events and behavior, not through moral lectures.

## Character knowledge

Do not treat character knowledge as an unlimited bag of trivia.

Prefer meaningful milestones:

- knows a principle;
- remembers a shared event;
- has learned a strategy;
- recognizes a place/object/person;
- changed a belief.

A future callback should reference these milestones when useful.

## Character introduction

Do not introduce the full cast at once.

Use staged entry:

1. core pair or small group;
2. recurring local characters;
3. later arrivals;
4. occasional specialists or visitors.

A new character should have a reason to exist beyond delivering information.

## World model

Wondervale should contain recognizable districts and landmarks with functions in both story and play.

A location can have:

- identity and visual landmarks;
- residents / recurring visitors;
- activities;
- history;
- current state;
- unlock conditions;
- future potential.

## Location lifecycle

Locations may evolve:

```
mentioned
→ visible
→ visitable
→ changed / repaired / opened
→ gains new function
→ becomes part of later stories
```

Example:

```
empty_corner_lot
→ construction_site
→ grocery_store
→ delivery_problem_episode
→ community_notice_board_added
```

The purpose is not endless city-building. World changes should create memory and new possibilities.

## World change classes

Classify persistent changes:

- **canonical** — permanent story fact;
- **functional** — unlocks a usable place or capability;
- **relational** — changes who interacts with whom;
- **seasonal** — changes presentation but is reversible;
- **cosmetic** — visual reminder without gameplay consequence.

## Continuity ledger

Maintain a machine-readable ledger for:

- canonical events;
- first appearances;
- location state transitions;
- character milestones;
- relationship milestones;
- important objects;
- open mysteries;
- resolved mysteries;
- promises / callbacks;
- learning callbacks.

## World coherence rules

- New locations should have a place on a stable map.
- A persistent building cannot silently disappear.
- Characters should not forget major shared events without explanation.
- A character's expertise must not expand merely because an episode needs an answer-giver.
- New technology or magic-like rules must follow previously established world rules.
- Visual changes expected to persist must be represented in continuity data.

## Tone

Wondervale can contain uncertainty, mistakes, disagreement, and mild tension.

Avoid making every adult automatically correct or every child character automatically reckless.

Problems should often allow multiple plausible ideas before evidence clarifies them.

## Representation

The cast and world should support varied families, abilities, cultures, interests, and ways of thinking without reducing a character to a demographic lesson.

Cultural stories should be authored or reviewed with appropriate context rather than treated as interchangeable decoration.

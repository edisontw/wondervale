## 2026-10-09 first-visit introduction UX fix

Owner reproduced an apparently frozen first visit **even in a clean Incognito session**: Milo/Nia/Finn appeared crowded, Town Square destination buttons did nothing, and the trio could only move after the user advanced the opening story dialogue. The existing engine intentionally locks world navigation before `square_explore`; the presentation misleadingly displayed interactive-looking destinations in both `preview` and `opening`, and positioned the companions by projecting tiny offsets from the same starting path node. This is an onboarding defect, **not an old save or browser cache defect**.

For the noninteractive `preview`/`opening` phases, render a separated trio in a visual-only Town Square without false affordances (navigation dock, world hotspot buttons, keyboard-tab walk affordance). Preserve the **Begin** primary action and add a plainly visible **Continue story** / **Skip introduction** action near the opening heading, above the large scene, in addition to existing exact-script caption controls. Once the introduction ends, restore the canonical navigable world, pointer/keyboard destinations and approved story without altered line IDs or gameplay. `FIELD-QA-FIRST-01` opens a genuinely fresh browser context and checks separated trio, no fake destinations, successful Begin and Continue, then live travel after Skip introduction. Build `20261009-e01-intro1`. Physical desktop/mobile verification remains outstanding.
